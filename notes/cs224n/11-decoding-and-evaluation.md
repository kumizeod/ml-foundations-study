# 生成策略与评测：模型得分不等于任务完成

[总目录](../README.md) · [上一主题](../cs224n/10-finetuning.md) · [下一主题](../cs224n/12-retrieval-and-factuality.md)

## 核心问题
贪心选当前最高概率 token；采样保留随机性；temperature 调整分布尖锐度；top-k 和 top-p 限制候选集合。它们影响质量、覆盖与重复性，评测必须记录具体配置。

## 指标与推导
若单次成功率为 p，且多次尝试独立同分布，则 k 次至少成功一次的概率是 1−(1−p)^k。真实 Agent 尝试常相关，因此不能直接用该式宣称 pass@k。若 n 个生成中 c 个成功，可用组合形式 1−C(n−c,k)/C(n,k) 估计相应的 pass@k，前提与采样协议必须交代。

## 实验设计
对编码任务分别记录解析成功、编译成功、公开测试、隐藏测试和回归测试。一个补丁能运行不等于正确。模型 A 比 B 高一点时，先检查配对任务差异、重复运行与置信范围，而不是只报总分。成本应含失败尝试和重试，而不只含最终成功路径。

## 与前一个项目的连接
高效评测抽样的是任务，不是随意砍掉失败的尝试。删掉最难的任务会提高表面分数，却改变了目标总体。绝对分数估计、模型排序、版本退步检测是三个不同目的。

## 自测与参考答案
问：temperature=0 是否保证整个 Agent 完全可重复？答：不保证，还受服务端实现、工具环境、并发和外部状态影响。问：多次重试后的成功率能叫单次成功率吗？答：不能，应说明尝试预算和选择过程。
